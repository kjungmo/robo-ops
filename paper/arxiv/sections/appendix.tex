\section{Reproduction}\label{app:repro}

All code is TypeScript under \texttt{src/fms/} of the repository (no runtime
dependencies); the benchmark, tests and paper tables are produced by
\begingroup\footnotesize
\begin{verbatim}
npm ci
npm test                        # unit and property tests (vitest)
bash scripts/regenerate.sh 8    # all ten sweeps, 7,200 runs
bash scripts/measure-timing.sh  # planner times: three repeats on an idle host
npm run paper:data              # tables/*.tex and figures/data/*.csv
npm run check:paper             # every number in the text and tables
\end{verbatim}
\endgroup
\begin{sloppypar}
All records in \path{paper/experiments/results/} were written by one run
of the regeneration script at commit \texttt{63a2db7} of the repository, on 8
worker processes (\texttt{bench-meta.json}); the code under
\texttt{src/fms/} and the benchmark driver have not changed since. Every run
is deterministic given its seed. Before the script replaces the committed
records it compares the new ones with them field by field, leaving out the
four wall-clock fields (\texttt{wallMs}, \texttt{plannerMs},
\texttt{allocMs}, \texttt{plannerMsPerTick}), and stops at any difference.
For the 6{,}600 runs that existed before, which had been written at earlier
commits on 1 and 10 worker processes, no field differed
(\path{paper/experiments/repro/regeneration.json}); the new records add
the counters of \cref{tab:diagnostic}, and the 600 runs of
\cref{tab:tpfree} are new. \texttt{npm run check:results -{}- <dir>} makes the
same comparison for a re-run written with
\texttt{npm run bench:fms -{}- -{}-out <dir>}, and the continuous-integration
workflow of the repository does so for the 420 first-round runs on other
hardware under Node.js 20, 22 and 24.
\end{sloppypar}

\begin{sloppypar}
Each kind of number has one source. Simulated quantities come from
\path{paper/experiments/results/<sweep>.json} (one record per run) and
its \path{_summary.csv}. Planner times come only from
\path{paper/experiments/timing/summary.json}, written by the timing
script: three single-process repeats of the planner, scaling and ablation
sweeps, each started only at a one-minute load average of at most 0.5, with
the load average, the core count and the largest CPU consumers before and
after each repeat in \texttt{host-<n>.txt} and the per-run times in
\texttt{repeat-<n>.csv}. The wall-clock fields inside the result records
were written under 8 workers and are not used. The last command is a guard.
It regenerates every table and figure data file and compares them byte for
byte; it recomputes every summary file from the per-run records; it
recomputes every numeral written in digits in the abstract, the sections,
this appendix and the figure captions from the committed records and from
constants exported by \texttt{src/fms}, and fails if a digit in that text
has no such check; and it checks which data column every plotted curve
reads. Three kinds of numbers are not recomputed but pinned, which means
that changing one fails the guard until a reviewed snapshot
(\path{paper/experiments/guard/pins.json}) is updated: numerals inside the
formulas and algorithms of \cref{sec:method}, numbers written as words
that the script does not list as a claim, and the two facts taken from the
git history (\cref{subsec:setup}). The guard does not check the logic of a
sentence, the references to tables and figures, or the drawing of the
figures beyond their data columns. The bounds stated in
\cref{prop:pp,prop:charge}, \cref{alg:astar} and \cref{eq:cost} are
exercised by unit tests (\path{src/fms/__tests__/properties.test.ts}).
\end{sloppypar}
Token passing is selected with \texttt{coordinator: 'tp'} or
\texttt{'tpts'} in \texttt{SimConfig}. Our adaptation to the setting of
this paper: the token table stores every robot's complete path with a
permanent rest at its end and no horizon, and space-time A* on it is bounded
by 20{,}000 expansions; a trip is planned as an empty leg to a pickup that
must stay free for the loading dwell, the dwell, and a loaded leg ending in a
rest at the dock; a robot without an eligible task drives to its home bay
(or rests where it is if no path exists) and takes no task on the way
(\texttt{tpFree: 'home'}; \texttt{'home-interruptible'} lets it request the
token at every tick of that drive, and \texttt{'faithful'} is the published rule of
\citet{ma2017lifelong}, adapted: the robot rests where its path ended and
requests the token at every tick; it moves only off the delivery cell of a
pending task, as in that paper, or, as two added triggers, off the pickup cell
of a pending task or off a charger slot, to the nearest home bay or dock in
which no other path ends and to which no pending task delivers; pickups are
not endpoints of this move because they lie on the aisles); a robot below
$\theta_{\mathrm{lo}}$ takes the nearest free charger slot that is not the
end of another path; and the task-swap step of TPTS only commits a swap if
the displaced robot still has a path to its home bay (under
\texttt{'faithful'}: to a Path2 endpoint), which keeps every step
conflict-free.
The operator console shows the
simulator at \texttt{/fms} (\texttt{npm run dev}).
